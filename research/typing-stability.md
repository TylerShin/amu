# 입력 중 한영 표시 안정성 비교

2026-10-23. `lock → lo차`와 다음 음절 초성을 입력할 때의 한영 왕복을 다룬 변경이다. 특정 단어·약어를 추가하지 않았으며 영어 seed, 한국어·초성 모델 파일과 libhangul 원본은 수정 전후 동일하다.

## 원인과 변경

이전 판독은 매 키의 문자열을 완성된 단어처럼 평가했다. `한ㄱ`의 마지막 초성에 미조합 비용을 부과해 `한 → gksr → 한그`로 되돌렸고, `lo`는 완성 영단어 근거가 부족해 `ck`를 별도 한글 음절로 분리했다. 표시를 유지할 근거와 최종 언어 판독 근거도 구분하지 않았다.

- `KoreanBuffer`는 완료 음절과 실제 libhangul의 활성 음절을 제공한다. `KoreanEvidence`는 직전 한글 조합에서 다음 초성을 기다리는 상태를 별도로 평가한다. 관측된 앞 음절과 다음 초성의 연결 또는 명시적인 된소리 Shift 근거가 필요하고, 온전한 영문 근거가 있으면 이 유지를 강제하지 않는다. 연결 근거는 기존 음절 bigram을 초성으로 투영해 초기화 때 만든다.
- `english`는 완성 철자와 계속 입력할 수 있는 철자 접두부를 구별한다. 두 글자 접두부도 한글로 완성되지 않고 뒤를 붙였을 때 영문 연결이 성립하면 불필요한 분절을 막는다. 입력 중 접두부 할인은 미완성 한글과 경쟁할 때만 적용한다. 완성된 `닭무침이`를 영문 접두부 유지로 밀어내지 않는다.
- `DisplayPolicy`는 이미 보이는 영문 키를 약한 한글 후보로 재해석하는 비용만 계산한다. 키당 0.75, 최대 2.0이며 원문 복구·초성·근거가 있는 전체 한글 및 한글 접두부는 면제한다. `selection`이 근거 점수와 이 비용을 함께 비교하되, 표시 비용 때문에 승자가 바뀌면 `Ambiguous`로 남긴다. 표시 유지 자체를 새 언어 확신으로 학습하지 않는다.
- `Session`은 직전 해석을 넘기고 선택 결과를 반영한다. 추가 타이머·입력 로그·네트워크·단어별 예외는 없다. 삭제는 실제 조합 상태를 유지하고, 수동 선택·고정 모드는 자동 표시 비용을 거치지 않는다. **공백·Finish에서는 마지막으로 보인 문자열을 그대로 확정한다.**

## 평가 기준

[실행 코드](../crates/amu-core/examples/evaluate_stability.rs), [의도 fixture](../crates/amu-core/tests/fixtures/stability.tsv), [측정 원본](typing-stability-metrics.tsv)을 함께 보관한다. 모든 평가에 빈 문맥·한글 네 단어 뒤·영문 네 단어 뒤를 사용했다. 한글은 고정 두벌식 조합, 영문은 원문, 초성은 개별 자음이라는 **명시적 의도**로 키마다 정답을 만든다. 자동 판독 결과를 정답으로 복사하지 않는다.

| 지표 | 의미 |
|---|---|
| 최종 정답 | 공백으로 확정한 문자열의 완전 일치 |
| 표시 정답 | 각 키 직후 문자열이 의도한 조합 상태와 완전히 일치 |
| 재해석된 키 | 이미 표시된 원시 키의 한글/영문 소속이 바뀐 횟수 |
| 반복 전환 키 | 같은 키의 언어 소속이 한 토큰 안에서 2회 이상 바뀐 키 수 |
| 안정 도달 키 | 그 이후 모든 표시가 정답인 최초 키 번호의 평균. 끝까지 틀리면 토큰 길이+1 |

`ㅎ → 하 → 한`, 받침 이동 등 정상 한글 조합은 언어 전환으로 세지 않는다. 반대로 틀린 영문을 끝까지 유지해도 흔들림 0일 뿐 정답으로 세지 않는다. 고정 사례의 첫 자음 `r → ㄱ`처럼 처음부터 의도를 맞혀야 하는 표시 기준도 완화하지 않았다. 단어마다 리셋하고 문맥을 주입하는 검사이며 실제 문장 순서를 재생한 결과는 아니다.

## 수정 전후

기준은 HEAD 자체가 아니라 직전 로컬 설치본 `v0.1.0-local.4a3196a4974e-dirty.6c19dd62-59fb-443b-a5a5-b5bc8091bbe6`에 해당하는 소스 snapshot이다. 그 상태에는 이미 수동 교정과 식별자 판독 변경이 들어 있었다. 같은 평가 코드와 정답 자료를 양쪽에서 실행했다.

### 공개 말뭉치

| 자료 | 최종 정답: 전 → 후 | 표시 정답: 전 → 후 | 반복 전환 키: 전 → 후 | 안정 도달 키: 전 → 후 |
|---|---|---|---|---|
| EWT test | 11,206 → 11,419 / 12,060 | 72,327 → 73,014 / 82,329 | 8,162 → 7,157 (12.3% 감소) | 2.82 → 2.56 |
| GSD test | 28,845 → 28,845 / 28,875 | 164,060 → 187,106 / 219,939 | 86,015 → 10,407 (87.9% 감소) | 5.40 → 2.41 |
| EWT dev | 11,053 → 11,240 / 11,895 | 71,691 → 72,293 / 81,546 | 8,004 → 6,976 (12.8% 감소) | 2.82 → 2.57 |
| GSD dev | 28,833 → 28,833 / 28,875 | 167,502 → 190,669 / 223,392 | 86,469 → 10,020 (88.4% 감소) | 5.44 → 2.41 |

EWT test는 소문자로 만든 4~64자 ASCII 어형 4,020종, dev는 3,965종을 세 문맥에서 평가했다. GSD는 한글 음절만으로 된 FORM 토큰을 중복 포함해 각 9,625개씩 평가했다. 행별 정답/오답 대조에서 영어 test 213건·dev 187건이 개선됐고 **각 자료에서 새 최종 오판독은 0건**이었다. 한글 최종 출력은 두 자료 모두 수정 전과 전부 동일했다. 이는 남아 있는 오류가 0이라는 뜻이 아니다.

이 수치는 개발 비교다. test 자료는 규칙을 점검하면서 재사용했다. dev 자료는 첫 별도 검사에서 `닭무침이` 3문맥의 새 오류를 드러냈고, 이를 보고 미완성 영문 할인의 범위를 수정했다. 따라서 최종 dev 결과도 손대지 않은 블라인드 점수가 아니다. 각 partition에서 중복 제거한 영어라도 partition 간 어형이 겹칠 수 있다.

### 의도를 적은 고정 사례

| 묶음 | 최종 정답: 전 → 후 | 표시 정답: 전 → 후 | 반복 전환 키: 전 → 후 |
|---|---|---|---|
| 영문 | 132 → 138 / 144 | 802 → 819 / 879 | 57 → 47 |
| 짧은 영문 어간 | 15 → 33 / 45 | 151 → 176 / 213 | 12 → 9 |
| 초성 | 18 → 18 / 18 | 30 → 36 / 54 | 12 → 0 |
| 한글 | 123 → 123 / 123 | 685 → 790 / 924 | 359 → 30 |
| 혼합 | 45 → 45 / 45 | 276 → 291 / 378 | 124 → 45 |

짧은 영문 어간 묶음은 `lock` 신고 후 추가한 15종×3문맥이며 개발 회귀다. 의도 fixture는 총 125종×3문맥, 375건이다. 실패한 사례도 빼거나 정답을 바꾸지 않았다.

| 입력 의도 | 수정 전 표시 | 수정 후 표시 |
|---|---|---|
| lock | `l → lo → loc → lo차` | `l → lo → loc → lock` |
| 한글 | `g → 하 → 한 → gksr → 한그 → 한글` | `g → 하 → 한 → 한ㄱ → 한그 → 한글` |
| ㄱㅅㄱㅅ | `r → ㄱㅅ → rtr → ㄱㅅㄱㅅ` | `r → ㄱㅅ → ㄱㅅㄱ → ㄱㅅㄱㅅ` |
| ai고 | `a → ai → 먁 → ai고` | `a → ai → air → ai고` |

`ai고`의 `air`는 최종 혼합 경계를 알기 전의 원문 표시다. 정확한 한글 접미부 조합을 모든 키에서 보여준 것으로 세지 않는다. `query`는 아직 `q → 벼 → 볃 → quer → query`, `graphql`은 `g → ㅎㄱ → gra → … → graphql`처럼 초반 전환이 남는다. `dock/rock/sock/tuck`, `dia`, `wasm` 등도 고정 평가에서 실패한다. 모든 영문과 모호한 접두부를 해결했다는 결론은 내리지 않는다.

기존 `core:evaluate`의 고정 130건, 문맥·혼합 경계·초성·미등록 식별자 검사를 유지했다. 생성 소문자 약어 평가용 seed는 446→452/600, 대문자는 588→588/600이다. 이 seed도 이전 수정부터 재사용했으므로 실행 출력의 `held-out generated` 명칭을 이번 변경의 블라인드 검증으로 해석하지 않는다.

## 지연과 복잡도

Apple M4 Pro, macOS 26.7.1, Rust 1.99.1 release. 두 버전을 순차 실행했고 모델 예열 후 `Session::process`만 재었다. 130개 고정 사례를 100회, 별도 64키 토큰을 100회 실행했다. OS 이벤트 전달·렌더링·Telegram 화면 지연은 포함하지 않는다. 단일 실행의 분포이며 엄격한 장비 간 성능 비교가 아니다.

| 코어 측정 | 수정 전 p50 / p95 / p99 | 수정 후 p50 / p95 / p99 |
|---|---|---|
| 일반 사례 68,500키 | 0.2 / 4.9 / 8.0 µs | 0.3 / 6.0 / 9.6 µs |
| 최대 길이 6,400키 | 12.2 / 36.3 / 208.4 µs | 14.4 / 44.4 / 220.9 µs |

표시 안정화로 계산량은 늘었다. p99가 일반 사례에서 1.6µs, 최대 길이에서 12.5µs 늘었으며 입력을 기다리는 타이머는 추가하지 않았다. [수정 전](typing-stability-latency-before.txt)·[수정 후](typing-stability-latency-after.txt) 전체 출력을 보관한다.

기존 경계 탐색은 한 키당 O(n²), 토큰 저장은 O(n)이며 n≤64다. 표시 재해석 비용은 후보당 O(n)이라 경계 전체의 차수를 늘리지 않는다. 초성 연결은 초기화 때 기존 bigram B개에서 파생하며 O(B) 공간 상한, 키 처리 조회는 HashSet 평균 O(1)이다. 키 처리 중 모델 로딩이나 사용자 입력 저장은 없다.

## 참고한 외부 평가

- [Araso의 공개 평가](https://github.com/nyttastudio/araso#평가-결과-학습에-쓰지-않은-데이터)는 학습에 쓰지 않은 어형 평가와 다른 언어 뒤의 문맥 평가를 구분하고, 규칙 조정에 사용한 점수를 별도로 설명한다. 공개 영/한 수치 99.82%는 다른 자료·구현의 작성자 측정이다. Amu와 같은 자료에서 실행한 경쟁 제품 비교가 아니다.
- [Whetten 외, 2023](https://arxiv.org/html/2302.12049)은 증분 인식에서 정확도·지연·이미 출력한 내용의 수정량을 함께 평가한다. 이 구분을 참고했다. Amu의 원시 키 언어 전환은 논문의 Edit Overhead와 다른 지표다. 한글의 정상 음절 재조합을 오변환으로 세지 않기 위해 별도로 정의했다.

## 회귀 검사와 검증 범위

`mise run check`는 최종 문자열, 키마다의 정확한 표시, 편집·모드·reset 경계, 원문 복구, 지표 자체의 정답성을 검사한다. 고정 한글에서는 현대 한글 11,172음절의 모든 입력·삭제 단계를 libhangul과 대조한다. 이 전수 검사는 자동 언어 판독의 정확도 100%를 뜻하지 않는다.

`mise run macos:smoke`에는 실제 NSTextView에서 `lock`, `한글`, 반복 초성의 키마다 문자열·marked text·커서·Space 확정을 확인하는 검사를 추가했다. 합성 NSEvent → Swift → C ABI → Rust → AppKit 경로다. Telegram·브라우저의 실제 시스템 IME 렌더링 검증과 구분한다. 설치본이 실행 중일 때 IMK 연결 이름 충돌 경고가 나므로 서버 객체 생성 성공을 새 서버의 OS 연결 성공으로 과장하지 않는다.

## 재현

```sh
mise run core:stability
mise exec -- cargo run --release -p amu-core --example evaluate_stability --locked -- crates/amu-core/tests/fixtures/stability.tsv .local/intent-trace.tsv
mise exec -- cargo run --release -p amu-core --example evaluate_stability --locked -- --english research/upstream/english-ewt/test.conllu .local/english-trace.tsv
mise exec -- cargo run --release -p amu-core --example evaluate_stability --locked -- --korean research/upstream/korean-gsd/test.conllu .local/korean-trace.tsv
mise run core:evaluate
```

`.local` 출력 디렉터리는 먼저 만든다. dev 비교는 마지막 corpus 파일명을 `dev.conllu`로 바꾼다. trace는 지정한 공개 fixture만 평가하며 실사용 타이핑을 수집하지 않는다. 큰 corpus·전체 trace는 저장소에 넣지 않는다.

수정 전을 재현하려면 **이 변경이 포함된 소스의 별도 복사본**에 [복원 patch](typing-stability-before.patch)를 `git apply research/typing-stability-before.patch`로 적용한다. 이 patch는 production Rust 소스만 이전 snapshot으로 복원하므로 현재 평가 코드·fixture·모델은 동일하게 유지된다. 작업 중인 체크아웃에 적용하지 않는다.
