# 후보 비교 정책 검증 — 2026-10-23

기준 코어는 `8de6f74b73e64cc9057474cc04ca7e95780076ee`다. 수정 전후에 같은 **의도 기준** 초성·영문 자료를 넣었다. 이전 평가처럼 앞 단어가 영어이면 초성 정답도 영문으로 바꾸지 않는다. 개발 중 사용한 회귀와 별도 test 자료의 결과를 구분한다.

`ㄴㅈ`·`ㄴㅎ`는 자동으로 뜻을 맞히지 못하고 원문 `sw`·`sg`를 남긴다. 초성으로의 근거 차이가 부족하기 때문이다. 원문 보존 정책 검사가 통과해도 초성 의도 정확도에 성공으로 세지 않았다. 정상 한글은 새 회귀가 없지만 기존 `새 → to` 등의 오류가 남아 있다.

새 문장 회귀 15개에는 `돼지갈비 vs 소고기`, `hello ㄹㅇ 한글`, `한글 cs 설정`, `fallback vs macos`, `삼성sdi 사고싶어`, Shift가 이어지는 정상 한글을 포함한다. 정책 테스트에서는 모호한 선택을 언어 이력에 다시 넣지 않는 것과, 두 혼합 경계가 경합해도 충분히 지지되는 혼합 문자열을 통째로 버리지 않는 것을 검사한다.

## 별도 영문 자료 평가

초성 모델을 만든 뒤 [UD English EWT test](https://raw.githubusercontent.com/UniversalDependencies/UD_English-EWT/4a4d77f599ea53cc405f85d0cec4b2f14f81d42b/en_ewt-ud-test.conllu)를 처음 평가했다. SHA-256은 `fa024f43dc5da3c5ac02563bc9bd0e974f46cbb1560823976a8f342a37dc494a`다. test 결과를 보고 모델·가중치를 다시 조정하지 않았다.

2~6자 ASCII 영문이며 a/e/i/o/u/y가 없는 FORM을 모두 추출하고 소문자화·중복 제거한다. 빈 문맥·한글 뒤·영문 뒤에서 의도를 영문으로 고정한다. 원문의 대문자 단서까지 제거한 어려운 조건이며 일반 타이핑 정확도가 아니다.

| 검사 | 수정 전 | 수정 후 |
|---|---:|---:|
| 전체 test 어형 64종 × 3문맥 | 128/192 | 132/192 |
| train에 없던 어형 39종 × 3문맥 | 71/117 | 69/117 |

전체는 4건 개선됐지만 **미등록 어형 부분집합은 2건 하락**했다. 기존 영문 선행 문맥의 우선권을 제거하면서 일부 입력의 초성 후보가 선택되기 때문이다. `wt → ㅈㅅ`, `qt → ㅂㅅ`처럼 양쪽 의도가 실제로 겹치거나 `gps → 헨`처럼 음절과 겹치는 실패도 남는다. 새 정책이 모든 미등록 약어 문제를 해결했다는 근거로 사용하지 않는다.

## 실행과 범위

```sh
mise run check
mise run repo:check
mise run macos:smoke
mise exec -- cargo run --release --locked -p amu-core --example evaluate_decoder -- research/upstream/korean-gsd/test.conllu .local/korean-after-candidates.tsv
mise exec -- cargo run --release --locked -p amu-core --example evaluate_short_latin -- research/upstream/english-ewt/train.conllu research/upstream/english-ewt/test.conllu
```

Rust·FFI 48개 검사를 통과했고, 이 중 조합 검사는 현대 한글 11,172음절을 전수 검사한다. AppKit은 초성·영문·모호한 원문 9종×3문맥의 표시·삭제·재입력·Space 확정 외에 기존 보안 입력, 혼합 경계, 재진입 검사를 통과했다. 실행 중인 설치본과의 IMK 연결 이름 충돌 경고는 기존 환경 제약이다. 이 결과는 외부 Telegram·시스템 설정에서 실제로 타이핑한 검증이 아니다.

모델 재생성 결과 SHA-256은 manifest와 동일하다. macOS 패키지에 모델·라이선스·재생성 스크립트가 들어가는지도 확인한다. Windows 실행 검사는 macOS에서 수행할 수 없으며 CI 결과와 별도로 구분한다.

일반 fixture 키와 최대 64키 입력의 release 지연도 함께 출력한다. 후보 비교기의 추가 상태는 최상위·차선·전체 후보 세 개로 제한된다. 실측 지연의 작은 변화는 OS 부하에 영향을 받으므로 속도 개선으로 해석하지 않는다. 전체 후보 탐색의 O(n²) 상한은 유지한다.
