# Amu 0.1.0 로컬 프로토타입

구현일: 2026-10-22. 개발자가 직접 타이핑하며 코어와 macOS 통합을 평가하는 최소 버전이다.

## 실행 흐름과 책임

```text
NSEvent
  → KeyTranslator: ANSI QWERTY + Shift를 공통 입력으로 변환
  → InputCoordinator: 코어 호출 → 결과를 순서대로 호스트에 제출
  → CoreSession / C ABI: 메모리 소유권·버퍼 길이·오류 코드 변환
  → Rust Session: 토큰 수명, 후보 선택·적용, 삭제·확정 정책
  → KoreanBuffer: 완료 음절과 현재 조합 음절을 분리해 보유
  → HangulComposer: 소유한 libhangul context로 자모 결합·삭제
  → Decoder: 전체 한글·전체 영문·양방향 혼합 후보 비교
  → 한국어 조합·음절 통계 / 영어 철자 특성 / 최근 언어 문맥
  → Update: consumed + commit + preedit
  → CompositionClient: 호스트의 조합 영역 갱신 또는 텍스트 확정
```

| 파일 | 책임 |
|---|---|
| `crates/amu-core/src/session.rs` | 키 처리의 진입점, 토큰 수명, 완료 경계와 삭제 정책 |
| `crates/amu-core/src/korean_buffer.rs` | 한글 후보의 완료 음절·현재 음절 및 조합 상태 소유 |
| `crates/amu-core/src/composer.rs` | libhangul context의 생성·호출·해제와 UCS-4 복사 |
| `crates/amu-core/src/language.rs` | 후보 생성·비교·분절 선택의 실행 흐름 |
| `crates/amu-core/src/korean_evidence.rs` | 조합 완성도·반복 자모·Shift 패턴과 음절 근거의 해석 |
| `crates/amu-core/src/korean_initials.rs` | 초성 표현의 형태 판별과 키별 독립 자음 표시 |
| `crates/amu-core/src/korean_statistics.rs` | 일반 한국어 자료의 음절 연결 통계와 분절 경계 점수 |
| `crates/amu-core/src/english.rs` | 문자 bigram, 모음·자음 배열, 대문자, 단어 힌트의 영문 점수 |
| `crates/amu-core/src/context.rs` | 최근 네 단어의 언어 경향; 원문은 보관하지 않음 |
| `crates/amu-ffi/src/lib.rs`, `include/amu.h` | Rust와 Swift 사이의 고정 C ABI |
| `macos/Sources/InputCoordinator.swift` | 코어 결과의 commit→preedit 반영, 재진입 확정 요청 처리 |
| `macos/Sources/AmuInputController.swift` | InputMethodKit 콜백·입력 메뉴·클라이언트 연결 |
| `macos/Sources/Playground.swift` | 설치 없이 같은 코어를 사용하는 AppKit 타이핑 창 |

조합기·언어 선택·세션·OS 효과를 분리하되 함수마다 trait이나 패키지를 만들지 않았다. 코어는 직접 호출하고 실제 호스트 경계에만 작은 `CompositionClient` 프로토콜을 둔다. FFI의 숫자 코드는 Swift의 `CoreOperation`에서 한 번만 변환한다.

## 현재 동작

- 현대 한글 두벌식, Shift 자모, 복합 중성·종성, 받침 이동과 삭제.
- 쌍자음 뒤까지 Shift를 누른 `qjfTJ`, `dkRK`도 `벌써`, `아까`로 판독한다. 반복 자모 `ㅎㅎㅎ`, `ㅋㅋㅋ`, `ㅠㅠ`와 `안녕ㅋㅋㅋ`, `ㅋㅋㅋ도`를 보존한다.
- 문장 첫머리·한글 문맥에서 `fd → ㄹㅇ`, `dw → ㅇㅈ`, `rt → ㄱㅅ`과 같은 두 초성 표현, 쌍의 반복, 뒤에 반복 자음이 붙는 표현을 판독한다. 영문 문맥·대문자·일반 영문 단어와 이어지는 철자 근거가 있으면 영문을 보존한다.
- 자동 판독·한글 고정·영문 고정. `hello dkssud` → `hello 안녕`, `rust gksrmf` → `rust 한글`.
- 문장 첫머리와 한글·영문 문맥에서 `ai`, Shift로 입력한 `AI`, `Ai`, `aI`의 원문을 보존한다. 두 글자 영문도 약어 형태로 비교하며 해당 문자열을 힌트 목록에 등록하지 않는다.
- 공백 없이 붙인 `ai고`, `qi에게`, `io에서`, `florp부터`도 영문→한글 경계 후보로 비교한다. 조사·접미사나 영문 약어 목록을 추가하지 않는다.
- 자동 판독에서 `tkatjdsdi tkrhtlvdj` → `삼성sdi 사고싶어`. 약어 등록 없이 `삼성qzx`, `설정florp`, `모델ZKD` 같은 후보도 판독하며 입력한 대소문자를 유지한다. `githubdp → github에`처럼 영문 뒤 한글도 지원한다.
- 한 단어를 marked text로 보유하고 공백·기호·Return·Tab·방향키·단축키 앞에서 확정한 뒤 원래 키를 호스트에 전달한다.
- macOS에는 밑줄과 조합 구간을 명시한 `NSAttributedString`을 전달한다. `MarkedText`가 표시 서식과 UTF-16 커서 범위를 만들고, 입력기·Playground 연결부가 같은 값을 사용한다. 글꼴·글자색·배경색은 호스트에 맡긴다. 서식 없는 문자열의 기본 강조에 의존하지 않으며 판독 결과나 단어 확정 시점은 바꾸지 않는다.
- `rkqtk` → `갑사`에서 Backspace → `갑ㅅ`. 일반 삭제로 이전 음절 경계를 되감지 않는다.
- 음절·영문·혼합 후보는 삭제 후 그 토큰의 언어 해석을 고정한다. 독립 초성 후보는 키 단위로 삭제하고, 다음 키를 입력할 때 다시 판독해 `ㄹㅇ → ㄹ → 라`처럼 모음 조합으로 돌아갈 수 있다.
- 한글→영문 혼합 후보에서는 영문 끝부터 삭제한다. `삼성sdi → 삼성sd → 삼성s → 삼성` 뒤에는 보관한 한글 후보의 실제 조합 상태로 돌아간다. `갑사api`에서 영문 세 글자를 지운 뒤 한 번 더 지우면 `갑ㅅ`이 된다.
- 영문→한글 후보에서도 삭제 시 실제 한글 조합 상태를 사용한다. `github갑사 → github갑ㅅ → github갑 → github → githu`를 유지한다.
- 공백은 단어를 확정하고 최근 언어 경향을 갱신한다. 외부 Finish, 포커스 이동, 모드 전환, reset, 소유 영역 밖 삭제는 문맥을 지운다. 한글 단어 뒤의 `go`는 `해`, 영어 흐름에서는 `go`로 판단한다.
- 원시 키 64개 또는 한글 버퍼 약 192바이트에서 표시 중 토큰을 확정하고 이어 입력한다. 한 음절의 변화 때문에 한글 버퍼는 검사 경계보다 소수 바이트 더 커질 수 있으나 FFI 1,024바이트 버퍼 이내로 제한된다.
- 포커스 종료·외부 commit 요청은 현재 표시를 한 번 확정한다. 재진입 요청은 현재 반영이 끝난 뒤 처리한다.
- 한 입력 대상에 하나의 Rust 세션을 소유한다. C의 문자열 포인터는 호출 내부에서 복사하고 밖으로 노출하지 않는다. 키별 디스크·네트워크 요청이나 입력 텍스트 로그는 없다.

## 판독 근거와 비용

별도 약어 목록 `english-suffixes.txt`는 삭제했다. `sdi`나 특정 회사명에 대한 조건문이 없다. 전체 한글, 전체 영문, 독립 초성, 한글→영문, 영문→한글 후보를 같은 진입점에서 비교한다. 후보 한 개에는 내부 경계를 최대 하나 둔다. 한글 부분은 실제 libhangul로 조합하고, 고른 후보만 편집 가능한 별도 context에 복원한다.

영문 점수는 기존 일반 영어 seed의 문자 bigram, 모음·자음 배열, 짧은 initialism 형태, 대문자 경계, 일반 단어 힌트를 함께 사용한다. 단어 목록에 없다는 이유로 후보를 버리지 않는다. 한국어는 조합 완성도와 자모·받침 특징을 보고, 혼합 후보끼리는 음절 연결 통계도 비교한다. 점수와 신뢰 차이는 수동 설계한 휴리스틱이며, 학습된 의미 모델의 확률이나 신뢰도로 해석하면 안 된다.

영문 연결 형태도 경계 근거로 사용한다. 기존 seed에서 끝자음군을 추출하고, 시작 자음군·모음 비율·단어 내부의 끝자음+다음 시작 자음 연결을 검사한다. 예를 들어 `fallback`의 `llb`는 `ll` 뒤에 `b`가 이어진 형태로 설명할 수 있다. 세 글자 이상에서 이 연결을 검사하고, 네 글자 이상에서 형태 근거가 있으면 기존 영문 비용 상한 1.1×키 수를 적용한다. 단어·약어·접미사를 새로 등록하지 않는다.

영문 뒤의 첫 한글 음절에 해당하는 키열은 libhangul로 확인한다. 그 키열까지 앞부분에 붙였을 때 영문 연결 형태를 유지하면, 대문자나 기존 일반 단어 힌트처럼 별도 경계 근거가 없는 후보는 제외한다. `fallba|ck`를 막으면서 `fallback|rk → fallback가`는 허용하는 이유다. 온전한 영문 형태를 앞부분의 한글과 나누는 후보에도 같은 보존 근거를 적용한다. 철자 형태와 후보 선택은 각각 `english.rs`, `language.rs`가 담당하며 세션의 삭제·확정 방식은 바꾸지 않는다.

전체 후보에서는 한글로 조합 가능하더라도 영문 후보를 항상 비교한다. 완성된 한글 후보에 자료에서 관측한 음절이 하나라도 있거나 소문자와 두벌식 Shift 자모 키가 함께 있으면 한글 판독의 추가 근거로 삼는다. 둘 다 없는 경우에만 작은 비용 1.5를 더한다. 자료에 없다는 이유로 후보를 배제하지 않으므로 `펌`, `쿡`처럼 드문 음절도 조합 구조로 보존할 수 있다. 이 비용은 단어 빈도나 언어 확률이 아니다.

완성 음절·영문 후보끼리는 한글 근거와 일반 영문 단어 힌트가 경합할 때 문맥으로 보정한다. 한글 Shift로 설명되지 않는 대문자는 전체·혼합 후보 모두 문맥 가중치에서 제외한다. 따라서 앞서 한글을 입력했다는 이유만으로 `AI`가 `먀`로 바뀌지 않는다. 한글 Shift로 설명되는 키열에는 소문자화한 단어 힌트를 적용하지 않아 `dO → 얘`가 `do` 힌트 때문에 밀리지 않게 한다.

영문→한글 경계는 앞뒤를 독립적으로도 검사한다. 앞부분에서 영문 점수가 한글보다 낮고 한글로 이어 읽을 근거가 약하며, 뒷부분은 관측된 한글 음절로 완성되고 영문보다 한글 점수가 낮으면 경계 근거로 채택한다. 이 경우 두 부분의 비용 합에서 경계 보상 3.0을 빼고, 다른 전체·혼합 후보보다 0.75 이상 유리할 때 선택한다. 단어 목록에 없는 두 글자도 이 경로로 후보가 된다. 뒤에 흔한 한글이 붙었다는 이유로 앞부분의 약한 한글 해석을 정당화하지 않는다.

반대로 전체가 관측된 한글 음절로 구성되면 대문자 근거 없는 영문 접두부 분절을 막는다. 접두부 자체가 여러 한글 음절이거나 완성 음절과 미조합 자모를 포함하면, 일반 영문 단어·대문자 근거 없이 약어로 바꾸지 않는다. `촘촘히`, `아이고`, `quick`, `florp` 같은 반례의 과도한 분절을 막는 일반 조합 규칙이다. 기존 영문 힌트와 한국어 모델 데이터는 바꾸지 않았다.

대문자 연속 구간이 모두 두벌식 Shift 자모 키에서 시작하고, 전체 한글 후보가 완성되어 자료에서 관측한 음절로 구성된다면 Shift를 늦게 놓은 입력으로도 설명할 수 있다. 이때 대문자 가중치만 제외하고 나머지 후보 근거를 비교한다. 원래 키열의 대소문자나 libhangul 입력은 바꾸지 않는다. 한글 후보에서 미조합 자모의 각 연속 구간이 같은 글자 두 개 이상이면 반복 표현으로 보존한다. 별도 문자열 목록은 없으며 명시적인 영문 고정 모드는 원문을 유지한다. 추가 검사는 O(n) 시간·O(1) 공간이므로 기존 탐색의 점근 복잡도는 바뀌지 않는다.

독립 초성은 미완성 음절과 별도 후보로 취급한다. 소문자 두벌식 자음 두 개가 서로 다르거나, 그 쌍이 반복되거나, 쌍 뒤의 나머지가 각각 두 번 이상 반복되는 자음 구간이면 표현 형태로 본다. 일반 영문 단어·연결 철자·모음으로 끝나는 기존 영문 접두부는 우선 보존한다. 예를 들어 `fallback` 입력 중 `fa`는 유지하고 `fd`는 문맥에 따라 `ㄹㅇ`로 읽는다. 영문 문맥이 우세하면 원문을 유지하고, 문맥이 없거나 한글이 우세하면 초성을 선택한다. 이는 의도를 확정하는 규칙이 아니며 같은 키의 충돌에 적용하는 기본 정책이다.

초성의 키 배치·표시는 `korean_initials.rs`, 영문 근거·문맥을 비교하는 선택은 `language.rs`, 삭제·확정·모음 입력 시 재조합은 `session.rs`가 맡는다. 선택된 초성은 한 키당 한 자음으로 표시해 `ㄱㅅ`을 `ㄳ`으로 합치지 않는다. 일반 음절의 libhangul 조합·삭제 상태는 그대로 유지한다. 형태 검사는 O(n) 시간·O(1) 추가 공간, 표시 생성은 O(n) 공간이며 단어 목록이나 모델을 추가하지 않는다.

한국어 통계는 [UD Korean GSD](https://github.com/UniversalDependencies/UD_Korean-GSD)의 고정 리비전 train 자료에서 **한글만으로 된 FORM 토큰**을 추출해 만들었다. 45,807토큰에서 음절 1,280종·음절 쌍 21,559종의 통계를 얻었다. 영문 약어나 전체 단어 조회표는 생성하지 않는다. [출처·라이선스·변환 과정](../models/korean/README.md)과 [SHA-256 명세](../models/korean/manifest.json)를 포함하고, `mise run model:korean`으로 재생성한다. 일반 빌드·타이핑에는 네트워크가 필요 없다.

최근 문맥은 같은 입력 대상에서 공백으로 확정한 네 단어의 언어 경향이다. 입력 원문, 주변 문서, 문장 의미를 읽는 방식은 아니다. `분야`와 `부sdi`처럼 동일한 키열의 의도가 모호하면 온전한 한글을 우선한다. 대문자라도 한글 Shift 자모 키로만 구성된 `PTP` 같은 경우는 여전히 모호하다. 이미 확정한 단어를 후행 문맥으로 다시 쓰지 않는다.

세션은 libhangul context 세 개(전체 후보·탐색용·선택한 혼합 후보)를 소유한다. 영어·한국어 통계는 최초 세션 생성 때 한 번 준비하고 읽기 전용으로 공유한다. 후보마다 context를 할당하지 않는다. 최대 64키 토큰에 대해 최대 128개 후보를 비교하며, 키당 **O(n²)**, 세션 가변 공간 **O(n)**이다. 토큰 전체 최악은 O(n³), 전체 N키 입력은 K=64 상한에서 O(NK²)다. 고정 모델 공간은 별도 O(M)이며 해시 조회는 평균 O(1)을 전제한다. 이는 아직 prefix 상태를 모두 캐시하는 증분 탐색은 아니다.

2026-10-22 이 Mac의 release 코어 측정에서 일반 fixture 키 p99 **5.8µs**, 64키 토큰 p99 **197.9µs**, 최초 세션·모델 준비 **1.89ms**였다. 초성 수정 전 같은 평가에서는 각각 6.0µs, 202.7µs, 3.76ms였다. 초기화 코드는 바꾸지 않았으며 이 측정 차이를 속도 개선 효과로 단정하지 않는다. 철자 검사는 O(n)이고 내부 자음군을 나눌 때 최대 네 위치만 검사하므로 키당 O(n²), 세션 공간 O(n) 상한은 그대로다. 문자열 출력 생성까지 포함하고 macOS 호스트 반영은 제외한다. 비교 제품보다 빠르다는 근거는 아니며 호스트 부하에 따라 달라진다.

## 검증

`mise run check`:

- Cargo fmt와 Clippy 경고 없음.
- Rust 기능 테스트 37개, C ABI 테스트 5개 통과.
- 기능 테스트 하나에서 현대 한글 **11,172개 음절**의 전체 키열·조합 결과·삭제 후 빈 상태를 모두 검사한다.
- 완료 음절 뒤 삭제, 자동 판독 기본 예제, 영어 삭제 후 새 한글 조합, 모드 전환, 세션 격리, 4,096키 입력의 유실 없는 분할 확정을 검사한다.
- C ABI의 UTF-8 길이, 메모리 레이아웃, 잘못된 입력의 상태 보존을 검사한다.
- `삼성sdi 사고싶어`, 대문자 약어, 한글 뒤 다른 약어, 혼합 구간 삭제·재입력, `분야/연아/인아`의 한글 보존, 모드 전환 및 64키 경계의 혼합 후보 확정을 검사한다. C ABI의 혼합 언어 코드는 2, 공백 확정 이벤트는 kind 4다.
- 미등록 약어 검사는 대상 영문이 일반 영어 힌트에 없음을 함께 검증한다. 문맥의 세션 격리·초기화 및 10,000회 편집 이벤트의 버퍼 상한도 검사한다.
- `저 벌써 아까 그거 다 만들었어요`의 공백 포함 입력, Shift를 다음 키까지 유지한 변형, 반복 자모의 표시·삭제·확정과 영문 고정 모드를 검사한다.
- `어떨까`의 마지막 `까`까지 Shift를 유지한 네 가지 키열을 한글·영문·빈 문맥에서 검사한다. 공백이나 다음 단어 입력 전에도 한글을 유지해야 한다.
- 짧은 영문·한글 26개를 빈 문맥, 한글 1·4단어 뒤, 영문 1·4단어 뒤에서 검사한다. 표시·공백 확정·중복 확정 방지와 `ai/AI/Ai/aI`의 삭제·재입력을 확인한다.
- 첫 대문자가 두벌식 Shift 자모 키와 겹치지 않는 494개 조합을 같은 5가지 문맥에서 전수 검사한다. 한글 Shift 의도와 겹치는 `RK` 등은 이 보존 계약에서 제외한다. `AI한글`, `한글AI`, `AI가`와 정상 Shift 한글도 문맥을 바꾸며 검사한다.
- 미등록 접두부 10종 × 한글 9종 × 문맥 5종의 450건을 검사한다. `ai갑사 → ai갑ㅅ → ai갑사`와 경계를 넘는 삭제·새 한글 입력도 확인한다. 정상 한글 14종·영문 14종을 같은 문맥에서 보존하는 검사는 140건이다. 이 회귀 검사들은 매번 `mise run check` 또는 `mise run windows:check`와 Linux·macOS·Windows CI에서 실행한다.
- 일반 단어 힌트에 없는 `fallback`, `callback`, `rollback`, `stack`, `switch` 등 16개 × 문맥 5종의 80건에서 표시·삭제·재입력·확정을 검사한다. 같은 영문 뒤에 한글 9종을 붙인 720건에서 영문 끝을 보존한 경계도 검사한다.

- 초성 표현 23종 × 문맥 5종, 같은 키의 대문자, 영문 반례 24종을 검사한다. 한영 양쪽에서 모음이 없는 서로 다른 자음 쌍 132종도 실제 libhangul 키 배치에서 생성해 표시·삭제·재입력을 검사한다. 모드·포커스·64키 확정과 `ㄹㅇ → ㄹ → 라`도 포함한다.

`mise run macos:smoke`:

- 합성 NSEvent를 **실제 NSTextView**의 키 처리와 marked text API에 전달한다.
- 조합 표시·삭제, 반복 commit의 중복 방지, 혼합 단어, `삼성sdi 사고싶어`의 약어 삭제·재입력·공백 확정, 미등록 `qzx`, 공백을 통한 문맥 전달·초기화, 선택 영역 교체, 동기 재진입 commit을 확인했다.
- Shift 플래그를 포함한 `벌써`, `아까`, `어떨까`와 반복 자모의 표시·확정·삭제를 확인했다. `어떨까 싶네요`는 실제 Space 키 이벤트를 포함해 검사한다.
- 문장 첫머리와 네 종류의 선행 문맥에서 `ai/AI/Ai/aI`, 미등록 두 글자 영문, `가/얘/펌/쿡`의 marked text와 Space 확정을 확인한다.
- 영문 접두부 5종 × 한글 5종 × 문맥 3종의 75건에서 공백 없는 혼합 경계·marked text·Space 확정을 확인한다. `갑사`의 실제 음절 경계를 유지한 삭제·재입력도 포함한다.
- `fallback`, `rollback`, `switch` × 한글 유무 3종 × 문맥 3종의 27건에서 영문 보존·혼합 경계·삭제·Space 확정을 검사한다. `fallback`은 매 키 입력 직후의 표시도 원문과 같아야 한다.
- 초성 표현 5종 × 문맥 3종의 15건에서 독립 자음 표시·삭제·재입력·Space 확정·중복 확정 방지를 검사한다.
- 고정 한글의 음절별 입력·삭제 10단계에서 문자열과 커서 위치, 명시적인 조합 밑줄, 호스트 글꼴·색상 보존 계약을 검사한다. 표시 변경이 토큰을 조기 확정하지 않고 최종 확정을 한 번만 수행하는지도 확인한다.
- Swift → C ABI → Rust → libhangul → AppKit 경로를 검사하지만 OS가 외부 앱에 전달하는 전체 IME 경로를 대신하지 않는다.

앱 번들의 서명·plist·상대 dylib 경로를 검사했고 현재 사용자 입력기로 등록했다. Playground 창 실행도 확인했다. Firefox·Chrome·Safari·TextEdit의 실제 시스템 입력기 타이핑 및 앱 간 전환 회귀 검사는 아직 완료하지 않았다.

별도 시작 검사는 InputMethodKit 객체 생성과 Objective-C 런타임의 `AmuInputController` 등록을 확인한다. 설치본이 실행 중이면 같은 연결 이름의 등록 충돌 경고가 나므로 이 검사 성공을 새 서버의 OS 연결 성공으로 해석하지 않는다. 설치 후 기존 시스템 입력 소스가 유지되는 것을 확인했다. 테스트 창에서 사용자가 입력 중인 내용은 후속 자동화로 덮어쓰지 않았다.

합성 약어 평가는 의도한 영문 끝부분과 한글 경계가 모두 맞아야 성공이다. 소문자 `kcwy`, `hdyr`, 대문자 `PTP` 등 실패 예도 출력한다. 생성 샘플은 실사용 분포가 아니므로 제품 전체 정확도로 일반화하지 않는다. 한국어 검증은 train과 다른 test 파일을 썼으며 실제 문장을 순서대로 타이핑한 평가는 아니다.

짧은 입력 수정 전 커밋 `5cfbdf8`의 [비교 기록](../research/decoder-before-short-input.txt)에서 짧은 영문·한글 문맥 검사는 95/130, 대문자 조합은 2,254/2,470이었다. 해당 수정 후 각각 130/130, 2,470/2,470을 유지한다.

혼합 경계 수정 전 `d5b0bf9`의 [비교 기록](../research/decoder-before-mixed-boundaries.txt)에서는 새 혼합 경계 검사가 90/450, 정상 한글 반례가 68/70이었다. 현재는 각각 450/450, 70/70이다. 같은 평가 코드로 한글 9,625토큰 × 세 문맥의 28,875건을 토큰별 대조한 결과 새 오판독 0건, 기존 오판독 개선 14건이었다. 영문 문맥의 `해체되었다 → go체되었다`는 해결됐고 `새 → to`, 한글 문맥의 `포함해 → 포함go`는 남아 있다. 전체 말뭉치 검사는 로컬에서 실행하며 일반 CI는 고정 회귀·생성 조합·편집 경계 검사를 실행한다.

영문 연결 수정 전 `d7dd043`의 [비교 기록](../research/decoder-before-english-continuity.txt)에서는 미등록 영문 보존이 10/80, 그 뒤의 한글 경계가 45/720이었다. 현재는 각각 80/80, 720/720이며 한글 28,875건의 토큰별 결과는 수정 전과 모두 같다. 기존 짧은 영문·혼합 경계·생성 약어 평가 결과도 유지한다. 새 검사는 수정 과정에서 사용한 회귀 사례이며 독립적인 블라인드 정확도가 아니다.

초성 수정 전 `1a56943`의 [비교 기록](../research/decoder-before-initials.txt)에서 새 초성 문맥 검사는 44/115였다. 현재는 115/115이고, 같은 키의 대문자 115/115, 영문 반례 120/120을 유지한다. 기존 한글 28,875건의 토큰별 결과는 수정 전과 같았다. 영문 seed 277종 × 문맥 5종의 1,385건에서도 정상 판독이 새로 깨진 사례는 없었다. 이 회귀 사례는 초성 규칙 개발에 사용했으므로 블라인드 평가가 아니다.

Shift·반복 자모 보존 전에는 평가용 소문자 447/600, 대문자 594/600이었다. 현재는 한글과 키열이 겹치는 `WJDL → 쩌이` 같은 경우 한글 쪽을 우선해 약어 복구율이 일부 낮아졌다. `ggg`와 `ㅎㅎㅎ`처럼 동일한 키열의 의도는 완전히 구별할 수 없으며, 자동 모드는 반복 표현을 우선한다. 붙여 쓴 자음이 앞 음절의 받침으로 결합하는 libhangul 동작 자체는 변경하지 않았다.

## 현재 제약

임의의 소문자 약어를 모두 구별하지는 못한다. 초성 자동 판독은 독립된 두 자음 표현과 반복 확장에 한정한다. 세 글자 이상의 임의 초성, 완성 단어에 붙인 초성, 한글 모음이 섞인 이모티콘까지 모두 인식하는 규칙은 아니다. `fd`를 영문 약어로 쓰려면 영문 문맥·대문자·영문 고정 모드를 사용할 수 있고, 영문 철자와 겹치는 자음을 입력하려면 한글 고정 모드를 사용할 수 있다. 고정 한글에서는 libhangul의 원래 겹자음 결합이 적용된다. 일반 영어 목록은 여전히 보조 근거이며, 새 판독기는 규칙·통계 기반의 실험 버전이다. 문장 의미 이해, 여러 번 교차하는 한영 분절, 후행 단어를 이용한 재판독, 개인 사전, 자동 변환 취소 기록은 아직 없다. 한글/영문 고정 모드로 조합 연결부를 따로 평가할 수 있다.

소문자 두 글자 뒤의 혼합 경계도 지원하지만 동일 키열의 의도 자체를 완전히 구별하지는 못한다. 예를 들어 `airy`는 영단어와 `ai교`의 키열이 같고 현재 자동 모드는 `ai교`를 선택한다. 자동 모드가 `ai`를 보존하는 만큼 같은 키열로 의도한 드문 한글 `먀`는 한글 고정 모드에서 입력해야 한다.

키 매핑은 ANSI QWERTY 위치와 Shift를 대상으로 한다. Caps Lock에 따른 대문자 처리, 다른 배열·세벌식·옛한글·한자 변환은 아직 제공하지 않는다. 붙여넣기는 호스트에 맡기며 붙여넣은 텍스트를 소급 변환하지 않는다.

호스트의 비동기 변경·선택 영역 이동을 일반화한 revision 확인과 부분 적용 복구는 아직 없다. `InputCoordinator`의 반영 완료는 API 호출이 끝났다는 뜻이며 화면 반영 확인을 의미하지 않는다. 정상 IME 콜백 계약에서 벗어나는 앱의 호환성은 별도 검증해야 한다. 이미 확정한 이전 단어를 자동으로 다시 쓰지 않는다.

Telegram macOS 앱에서 자동·고정 한글 모드 모두 떨림·잔상이 보고되었고, 사용자가 같은 앱의 기본 한국어 입력기에서는 정상임을 확인했다. 조합 서식 변경은 이 문제의 비교용 수정이며 실제 앱의 개선 여부는 아직 확인하지 않았다. 별도로 자동 판독 중 `한 → gksr → 한그 → 한글`처럼 다음 음절의 초성을 영문으로 잠시 재해석하는 현상이 재현된다. 현재 회귀 검사의 완성 단어 정확도와 이 중간 표시의 안정성은 별개이며, 이번 서식 변경은 중간 판독을 수정하지 않는다.

Windows TSF 레이어는 같은 C ABI를 사용하며 x64·x86 MSVC 빌드를 제공한다. 키 번역, 코어 수명, 조합 범위 편집, COM 등록을 분리한다. Windows 안에서 x64·x86 대상을 빌드하며 다른 OS에서 Windows로 cross compilation하지 않는다. Linux 입력기 연결은 아직 없다. [Windows 설치·검증 범위](install-windows.md)를 참고한다. macOS 번들은 개발용 ad-hoc 서명이며 공증·자동 업데이트를 포함하지 않는다.

## 빌드·설치 유지보수

- mise로 Rust 1.99.1, rustfmt/clippy, Node 22.22.1을 고정한다. Swift/SDK는 Xcode에서 공급한다.
- Cargo.lock을 포함하고 빌드·검사에 `--locked`를 사용한다. 현재 Rust 외부 crate 의존성은 없다. Windows C++ 연결부는 MSVC와 Windows SDK를 사용한다.
- libhangul 소스는 지정 revision의 조합 관련 7개 파일을 수정 없이 포함한다. `COPYING`과 출처를 유지하고 별도 공유 라이브러리(dylib/DLL)로 배포한다.
- 빌드는 새 디렉터리에서 서명·검증한 뒤 기존 번들과 교체한다. 실행 중인 앱의 바이너리 파일을 덮어쓰지 않는다. 기존 빌드는 `dist/.previous/`에 남는다.
- 설치 시 동일 식별자의 기존 앱은 `~/Library/Application Support/Amu/backups/`에 보존한다. 다른 식별자의 동명 앱은 덮어쓰지 않는다.
- `mise run macos:install`은 빌드·백업·교체 후 정상 종료·시작과 실행 버전 응답을 확인한다. 설치 전 다른 입력기로 전환한다. Amu가 선택되어 있거나 조합이 남아 있으면 종료를 거부하며 다른 입력기나 시스템 서비스를 종료하지 않는다.
- main의 CI 성공 후 검사한 번들을 ZIP으로 묶어 개발 릴리스로 공개한다. 수동 ZIP 설치는 이전 프로세스가 남을 수 있어 로그아웃·로그인이 필요하다. [배포 흐름](maintaining.md)과 [설치 안내](install-release.md)를 참고한다.

다음 구현 순서는 실제 호스트 호환성 trace 확보, 혼합 분절·보존 규칙 확장, 실사용 문맥 평가와 OS 반영까지 포함한 지연 측정이다. 조사 단계의 전체 설계가 이미 구현됐다는 뜻은 아니다.
